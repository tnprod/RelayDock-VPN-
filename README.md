# RelayDock — VPN с постоянными ссылками

**Меняйте выходной сервер, а не ссылки у всех пользователей.**

[Скачать для Windows](https://github.com/tnprod/RelayDock-VPN-/releases) · [English](README.en.md) · [Сообщить об ошибке](https://github.com/tnprod/RelayDock-VPN-/issues)

Свой VPN обычно начинается с одного VPS и одной ссылки. Потом сервер приходится менять: заканчивается аренда, не устраивает связь или хочется попробовать другой хостинг. И снова нужно переносить настройки и объяснять близким, какую ссылку теперь добавить в приложение.

RelayDock появился из этой задачи. Он запускается на вашем компьютере, открывает управление в браузере и помогает настроить VPN и Telegram-прокси на своих VPS. В схеме с отдельным входом выходной сервер можно заменить, сохранив уже выданные ссылки и QR-коды.

Это **2.0 beta 1**. Основной сценарий проверен на настоящих серверах; сейчас проекту нужны первые пользователи, сообщения о непонятных шагах и проверки в других условиях.

## Как это устроено

```text
Ваше приложение → постоянный входной VPS → сменяемый выходной VPS → интернет
```

Ссылка ведёт на входной VPS. При замене выхода RelayDock переносит настройки подключения на новый сервер, проверяет его и переключает маршрут на входе. Адрес входа и клиентские секреты остаются прежними.

Компьютер с RelayDock нужен для управления. После настройки службы работают на VPS самостоятельно — программу можно закрыть.

Можно настроить и прямое подключение к одному VPS. Но при смене его IP для сохранения адреса в ссылке потребуется собственный домен и обновление DNS. Постоянная ссылка также не спасает от блокировки самого входного адреса.

## Что уже работает

- Добавление VPS с доступом по паролю, SSH-ключу или через SSH-agent.
- Настройка VLESS + REALITY на Xray и необязательного Telegram MTProxy.
- Прямое подключение или схема с отдельными входом и выходом.
- Сохранение профилей, показ ссылок и локальная генерация QR-кодов.
- Замена выхода с проверками HTTPS и протокола Telegram. Если переключение не подтверждено, серверный таймер через 120 секунд возвращает предыдущий маршрут.
- Выбор портов и дополнительные настройки подключения в мастере.

Старый выходной VPS автоматически не удаляется. На сервере создаются отдельные службы `relaydock2-*`; программа не останавливает чужую службу ради занятого порта. При активном UFW добавляются разрешения выбранных TCP-портов. Правила сети у хостера нужно настроить отдельно.

## Попробовать

Нужны Windows x64 и один VPS для прямого подключения либо два VPS для схемы с отдельным входом. Поддерживаемая серверная среда: **Ubuntu 24.04 x86_64**, Python 3, systemd и доступ `root` либо пользователь с `sudo -n`.

1. Скачайте Windows-архив из [Releases](https://github.com/tnprod/RelayDock-VPN-/releases), распакуйте его целиком и запустите `RelayDock.exe`. Python и Node.js для готовой сборки не нужны.
2. Добавьте серверы. При первом подключении сверьте отпечаток SSH-ключа сервера с доверенным источником — например, консолью хостера — и подтвердите его. Это ключ, которым сервер представляется вам, а не ваш файл для входа.
3. В разделе «Подключения» выберите «Настроить VPN», задайте схему и просмотрите план установки. Сначала лучше использовать отдельные тестовые VPS.
4. После успешной проверки откройте «Ссылки и QR» и добавьте подключение в совместимое клиентское приложение. Для другой точки выхода используйте «Заменить выход».

Приложение устанавливает службы и меняет сетевые настройки VPS. Запускайте одну копию RelayDock для управления одной схемой и сохраняйте доступ к консоли хостера.

## Где сейчас граница беты

На трёх VPS проверены установка, настоящий трафик HTTPS и Telegram, замена выхода и обратное переключение. После каждого переключения клиентские ссылки совпали посимвольно. Прошли 28 автоматических тестов; отдельно проверена Windows-сборка. Подробнее — [в отчёте](docs/verification.md).

Пока нет полного управления произвольной 3x-ui, переноса её базы, мастера защиты SSH, зашифрованного экспорта на другой компьютер и готовых сборок для macOS/Linux. Существующая 3x-ui не становится управляемой панелью RelayDock: новые подключения используют отдельный Xray. Импорт старой схемы ограничен службами `codex-forward-*` и `codex-exit-*`, которые поддерживает текущий импортёр.

Windows-сборка ещё не проверена на отдельной чистой машине. Все варианты потери сети, отключения питания и аварийного завершения не моделировались. Независимого аудита безопасности не было. Таймер отката помогает при неудачном переключении, но не заменяет резервные копии и доступ к серверу.

## Ваши данные

Облачный аккаунт RelayDock не нужен. Интерфейс доступен только на локальном компьютере; телеметрии нет. Программа подключается к вашим VPS, получает необходимые компоненты из официальных релизов и использует внешние узлы для проверки связи.

В Windows данные лежат в `%LOCALAPPDATA%\RelayDock`. Профили и добавленные SSH-ключи шифруются; главный ключ защищён Windows DPAPI для текущего пользователя. Пароли SSH не сохраняются. В исходном Linux-варианте главный ключ защищён правами файла.

Локальная резервная копия профиля находится в той же базе и не защищает от потери диска. Один `state.db` без `vault.key` не восстановит секреты; простое копирование на другой компьютер не является поддерживаемым переносом.

Не прикладывайте к публичным Issues свою папку данных, приватные SSH-ключи, пароли, полные ссылки подключения или QR-коды. В примерах используйте вымышленные адреса.

## Запуск из исходников

Python 3.11+. Из каталога проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
.\.venv\Scripts\python launch.py
```

Собранный интерфейс включён в исходники. Для его изменения нужны Node.js и pnpm:

```powershell
cd frontend
pnpm install --frozen-lockfile
pnpm run build
```

Проверки: `python -m pip install -r requirements-dev.txt`, затем `python -m pytest tests -q`. Windows-сборка: `build_windows.ps1` из окружения с установленными зависимостями разработки. При запуске из исходников и в самостоятельной сборке компоненты Xray/mtg скачиваются при необходимости; версии закреплены, SHA-256 проверяются. Готовый Windows-релиз содержит эти компоненты.

Стек: Python, FastAPI, AsyncSSH, SQLite, React и TypeScript. [Архитектура](docs/architecture.md).
