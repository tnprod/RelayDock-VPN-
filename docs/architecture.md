# Архитектура RelayDock 2.0 beta 1

Локальная FastAPI служба обслуживает собранный React-интерфейс только на loopback. Начальная авторизация использует фрагмент URL и HttpOnly cookie. API проверяет Host, источник запросов и служебный заголовок.

SQLite хранит серверы, публичное состояние подключений и зашифрованные профили. Vault шифрует секреты Fernet; в Windows главный ключ защищён DPAPI. Загруженные файлы SSH-ключей хранятся отдельно в зашифрованном виде. Пароли операций остаются в памяти задачи и не сохраняются.

Manager выполняет импорт существующей схемы, установку и замену выхода, протокольные проверки и резервирование. На одну копию приложения допускается одна операция настройки одновременно. Проверки серверов и чтение состояния доступны отдельно.

Установщик получает закреплённые официальные runtime-файлы с опубликованной SHA-256, проверяет их локально и после передачи. На VPS выполняется фиксированный Python-код; данные передаются через SSH stdin. Создаются собственные службы systemd, конфигурации и ограниченные разрешения UFW. Произвольные команды пользователя в shell не подставляются.

Перед сменой входного маршрута создаётся серверная транзакция с таймером возврата. После настоящих проверок HTTPS и Telegram приложение подтверждает транзакцию; без подтверждения сервер восстанавливает предыдущую конфигурацию. Клиентские UUID, ключи, секреты и входной адрес принадлежат профилю, а не сменяемому выходу.

Полное управление произвольной 3x-ui и мастер изменения безопасности SSH пока не реализованы. Существующие панели сохраняются.
